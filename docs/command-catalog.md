# Command catalog

Status: accepted public command design, 2026-10-12 (D-30, FR-79). Commands, selectors, argument conventions, defaults, and recovery contracts are accepted. This document does not claim an implementation or validate unresolved OS, integration, storage, or transport mechanisms.

Authority: [overview](overview.md), [concepts](concepts.md), [functional requirements](functional-requirements.md), [non-functional requirements](non-functional-requirements.md), and [decisions](decision-map.md). This catalog is a command design, separate from implementation planning and transport design.

## 1. Invocation and shared arguments

```text
stratosphere [GLOBAL-OPTIONS] RESOURCE COMMAND [ARGUMENTS] [OPTIONS]
```

In the signatures below, square brackets denote optional arguments, `A|B` denotes an enum, and uppercase words denote typed values. Literal brackets are not passed to the CLI. Options may follow positional arguments. Names/paths containing spaces must be quoted by the invoking shell. No command performs wildcard expansion of resource selectors.

| Global option         | Definition                                                                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--help`              | Show help for the selected command/group; make no changes.                                                                                                                                    |
| `--version`           | Print CLI version without contacting the daemon.                                                                                                                                              |
| `--format text\|json` | Default `text`; JSON exposes structured results, resolved IDs, warnings, operation IDs, and errors.                                                                                           |
| `--socket PATH`       | Select a local user socket; omitted uses the installation's default user socket. No remote/network endpoint.                                                                                  |
| `--no-wait`           | For operations, return after durable acceptance with an operation ID. Default waits for completion or an actionable blocked/interrupted/partial-failure state. Invalid on read-only commands. |
| `--timeout DURATION`  | Bound client connection/wait time; omitted has no client wait deadline. Expiry does not cancel accepted daemon work.                                                                          |
| `--non-interactive`   | Never read prompts; purge without valid consent returns `confirmation-required`. Ordinary commands already do not prompt.                                                                     |

`DURATION` is a positive decimal followed by `ms`, `s`, `m`, or `h`. `TIME` is an RFC 3339 timestamp with an explicit timezone. `COUNT` is a positive integer. `BOOLEAN` is `true|false`. Numeric geometry is finite, in macOS logical points, not pixels. Commands reject unknown options, invalid enums, and mutually exclusive arguments before mutation.

All commands have CLI and typed daemon action/query equivalents. UI and hotkeys use those same actions, not CLI parsing. Presentation actions are routed to the enabled UI client; a disabled/unavailable UI produces a structured error. JSON-RPC method names, schemas, framing, subscription recovery, and socket location are separate transport design work (FR-52–FR-56, Q-10).

## 2. Selectors and target resolution

| Type                                                                          | Accepted form and meaning                                                                                                                                                            |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `WORKSPACE`                                                                   | `id:UUID`, an absolute logical path such as `/Work/Editor`, or `focused`, `project`, `visible:DISPLAY`.                                                                              |
| `WINDOW`                                                                      | `id:UUID` or `focused`; always a managed identity, never a title or ephemeral AX handle.                                                                                             |
| `DISPLAY`                                                                     | `id:DISPLAY-ID`, `main`, or `focused`. IDs come from `display list`; `focused` resolves the keyboard-focused window's display, then the focused leaf's effective display, then main. |
| `CONTAINER`                                                                   | `id:CONTAINER-ID` or `focused`; an engine-local layout container, scoped by `--workspace`.                                                                                           |
| `APP`                                                                         | `bundle:BUNDLE-ID`; no ambiguous display-name/process-name matching.                                                                                                                 |
| `SNAPSHOT`, `OPERATION`, `UNDO`, `TRASH`, `NOTIFICATION`, `CHILD`, `LAUNCHER` | Exact IDs returned by their list/show commands.                                                                                                                                      |

Paths are semantic workspace paths, not filesystem paths. Lookup follows normalized case-insensitive sibling names. `focused` denotes the daemon's logical focused leaf/window and remains meaningful when an unrelated app has keyboard focus. A missing focused window is an error, not an implicit choice of another window. `project` is the active top-level ancestor. `visible:DISPLAY` fails when that display has no visible leaf. Bare names, relative paths, substring selectors, and silent ambiguous matches are excluded from this proposal. A literal workspace named `focused` remains addressable by absolute path or UUID.

`NAME` is one normalized nonempty workspace component, case-insensitively unique among siblings; `/`, NUL, `.` and `..` are rejected. Additional filesystem restrictions must be established with the storage design (Q-09), then exposed by validation rather than silently rewriting user input.

Selectors resolve to IDs at command acceptance. A path rename afterward does not retarget an accepted command. Dynamic navigation choices resolve during ordered planning; pending app-effect steps replan using current ownership and state. Queries are passive: no restore, recency update, or focus. A list includes unarchived closed/hidden items unless filtered. Archived items require `--include-archived`; Trash is accessed through `trash`.

Unless its signature requires a target, a workspace command targets `focused`, a window command targets `focused`, and a layout command targets the focused window's leaf, falling back to the focused leaf. Destructive structural commands require explicit targets. No operational command bypasses the archive seal, including via descendants. Inspection, history preview, and backup export remain allowed (FR-12).

`--to WORKSPACE` on window/app insertion resolves a parent using remembered leaf selection for the source window's effective display (or focused display for app creation), then recency and child order. Results expose the resolved leaf. It never distributes one window across multiple leaves. An explicit destination without eligible leaves fails. Only adoption of a new ordinary window with no visible leaf creates the required Desktop fallback (FR-14).

## 3. Results, errors, ordering, and Undo

Read queries return a record/list; list results include stable IDs and pagination metadata. List commands accept `--limit COUNT` (default 100) and `--cursor CURSOR`. A cursor is opaque, tied to that query, and has an explicit expiry error; clients must not infer it from names or timestamps. `--all` retrieves all pages and is exclusive with `--limit`/`--cursor`. Query ordering is deterministic: tree presentation order for workspaces, layout order then floating-group order for windows, newest first for history/operations/Undo/Trash/notifications, configured order for launchers/actions/modes, and stable ID order otherwise. Active-session navigation order has its own snapshot rules.

Accepted mutations report operation ID, resolved targets, changed/no-op state, succeeded/failed/pending/superseded steps, warnings, fidelity, and resulting Undo ID when eligible. A requested state already in effect is a successful no-op. Unsupported app behavior is a typed result, not fake success. Required capture/persistence failure is distinct from accepted best-effort/unavailable restoration fidelity.

Operation states: `pending`, `running`, `blocked`, `succeeded`, `partial`, `failed`, `cancelled`, `interrupted`, `superseded`. Blocked means dependent steps wait while other work can proceed. Partial means the attempt stopped with both completed and unsuccessful steps. Cancellation preserves actual effects; superseded means newer intent displaced remaining work. Operation details state which recovery commands are available.

Errors include `invalid-argument`, `not-found`, `ambiguous-match`, `name-conflict`, `invalid-tree`, `unarchive-required`, `unsupported`, `permission-required`, `storage-failed`, `capture-failed`, `confirmation-required`, `consent-expired`, `undo-unavailable`, `ui-unavailable`, `daemon-unavailable`, and `timeout`. Errors include affected IDs, actual partial effects, and available recovery actions where applicable. No arbitrary confirmation gate is added for ordinary actions.

CLI exit codes: `0` successful query/completed action/no-op or accepted `--no-wait` operation; `2` invalid invocation; `3` rejected request; `4` failed/partial/cancelled/superseded operation; `5` blocked/interrupted work requiring attention; `6` missing/stale purge consent; `7` client transport/timeout failure. JSON error codes are more specific. `operation show` succeeds as a query even if the inspected operation failed; `operation wait` uses the operation outcome.

Separate CLI invocations have separate client queues. To guarantee a sequence, wait for each completion in the shell or use an action sequence; `--no-wait` followed by another invocation is not a completion barrier. A shell-invoked CLI has its own queue, avoiding a parent-action deadlock. Never hold the mutation queue across AX, integration, launcher, or shell waits (FR-57, FR-75–FR-78).

Structural actions retain before-state and expose persistent Undo where safe. Eligibility is computed from actual effects and declared fidelity, not guaranteed by a command name. Focus/presentation changes, arbitrary shell actions, and generic app effects are not promised structural Undo. History restore provides structural before-state. Purge consent cannot authorize erasing retained history/Undo. There is no Redo command in this proposal (FR-40, Q-12).

Generated-child naming: use `Contents`, then the lowest available `Contents 2`, `Contents 3`, and so on, respecting normalized sibling uniqueness and reserving the incoming child's name before choosing. An explicit wrapped name conflicting with an incoming/existing child rejects the request before effects. Each wrapping reports its chosen name. This resolves the generated-child naming part of Q-07.

Merge completion is defined per source: all required structural transfers and compatible content merges must complete durably before that source archives. Unsupported merge compatibility keeps separate windows and does not by itself fail consolidation. Capture/persistence/matching/restoration failures leave that source unconsumed with recorded partial progress; there is no speculative rollback. Later sources proceed only when independent of the failed steps. Revalidate before retry. This resolves the per-source completion contract in Q-07; integration-specific convergence still requires validation.

## 6. Layout and display commands

Trace: C-02, C-06; FR-03–FR-07, FR-15–FR-21.

All layout commands accept `--workspace WORKSPACE`; it must resolve to an unarchived leaf without implicit parent-to-leaf selection. Container IDs are engine-local and not portable window identities. Structural layout edits preserve window ownership.

| Signature                                                                                    | Behavior and defaults                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `layout engine bsp\|i3 [--workspace WORKSPACE]`                                              | Switch the entire leaf's tiled engine; retain the inactive engine's saved state and reconcile membership.                                                                                                                                                                                          |
| `layout split horizontal\|vertical [--window WINDOW] [--ratio FRACTION]`                     | For BSP, set the target tile's next insertion axis/ratio; for i3, create/select a split container around the target. Default target focused tile; ratio defaults to configured insertion ratio. Fraction must be strictly between 0 and 1. Horizontal means left/right; vertical means top/bottom. |
| `layout container split-horizontal\|split-vertical\|tabbed\|stacked [--container CONTAINER]` | Set the selected i3 container's arrangement. Default focused tile's parent; fail when no container exists or engine is BSP. Children/membership retained.                                                                                                                                          |
| `layout resize left\|right\|up\|down --by SIGNED-SIZE [--window WINDOW]`                     | Adjust the indicated tile boundary, constrained by minimum dimensions. | `layout swap WINDOW --with WINDOW`                                                           | Exchange tiled positions in the same leaf/current engine. | `display list`                                                                               | Show connected display IDs, geometry, usable area, main flag, visible leaf, and known disconnected binding IDs.                                                                                                                                                                                    |
| `display show [DISPLAY]`                                                                     | Show saved binding references and current placement; omitted display is focused.                                                                                                                                                                                                                   |

Directional tile moves use the engine tree's nearest boundary neighbor in the requested direction; ties follow engine traversal. For tabbed/stacked siblings, left/right select previous/next sibling for tabbed, up/down for stacked. Other directions traverse enclosing splits. This deterministic behavior does not imply a private-API mechanism.

Restore requires root identity match, keeps selected root name/parent, and restores saved semantics/history/eligible Undo with before-state. Imported records revalidate Undo; preserve current retained records and all their references. No unrelated deletion or replacement of excluded data. New does not focus; restore reconciles currently visible leaves only. Reject identity collisions outside safely reclaimable captured structure, archive-sealed transfers, or unsupported schema. |

Backup container encoding, migrations, reference storage, and atomic import mechanics remain Q-09. The public import modes are accepted; implementation must not treat this as permission to invent unsafe collision handling. There is no retained-history erasure command because its scope requires a separate product decision. How the 30-day Trash retention interacts with explicit permanent-purge consent needs a product decision; this catalog neither removes retention nor assumes expiry alone authorizes permanent purge.

## 11. Operations and explicit recovery

Trace: C-09; FR-23, FR-29, FR-40, FR-53–FR-57, FR-75–FR-78.

| Signature                                                                                                       | Behavior and defaults                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `operation list [--state STATE] [--item ITEM]`                                                                  | List durable operations newest first; item filter selects operations touching that identity/subtree.                                                                                                                                                                                                                                                                                                             |
| `operation show OPERATION`                                                                                      | Show current state, affected identities, actual effects, step status, fidelity, blocked causes, and recovery actions.                                                                                                                                                                                                                                                                                            |

| `operation cancel OPERATION`                                                                                    | Stop unissued cancellable steps, preserve completed/in-flight effects and captured state. | `operation retry OPERATION [--step STEP-ID]`                                                                    | Retry currently failed retryable work, default all eligible failed steps. Resolution choices are typed daemon results, not arbitrary overrides. `CANDIDATE` is a short-lived opaque candidate ID supplied by that step's recovery result, for either managed or previously unmanaged live windows; it is never an AX handle. Revalidate candidate identity and compatibility before effects; expired or no-longer-valid candidates return an error and refreshed choices. `--adopt-current` must explicitly identify both incoming context (via step) and current content (via window), preserving both before-states where available. Skip is unavailable when it would violate required invariants or necessary capture.

## 13. Representative examples

```sh
# Create without launching or switching; then explicitly activate.
stratosphere workspace create Work
stratosphere workspace create Editor --parent /Work
stratosphere workspace focus /Work/Editor

# Move ownership separately from focus.
stratosphere window move focused --to /Work/Browser
stratosphere workspace focus /Work/Browser

# Parent binding overrides descendants only for that activation.
stratosphere workspace bind /Work main
stratosphere workspace focus /Work

# Explicit group and engine changes.
stratosphere window group focused free-centered
stratosphere layout engine i3 --workspace /Work/Editor

# Restore window state while preserving its current owner.
stratosphere history restore window:id:WINDOW-UUID --snapshot SNAPSHOT-ID

# Inspect durable work and resume only on an explicit request.
stratosphere operation show OPERATION-ID --format json
stratosphere operation resume OPERATION-ID

# Purge automation uses daemon-bound consent, not a stale yes/no answer.
stratosphere trash purge TRASH-ID --preflight --format json
stratosphere trash purge TRASH-ID --consent TOKEN --non-interactive
```

The uppercase IDs in examples are placeholders to replace with actual returned IDs, not accepted UUID strings.

## 14. Acceptance boundaries and verification

This design covers the whole initial product command surface, not just the current foundation implementation. Accepted contracts include generated-child naming, open/focus equivalence, parent insertion resolution, history capture/archive handling, clone/history separation, merge completion, navigation sessions, operation states/exit codes, backup modes, and update delegation. Implementation planning is separate and has not started.

Research-dependent commands return truthful capability/error results until their required release mechanisms are validated; this does not waive accepted product requirements. Q-01–Q-06, Q-08–Q-13 retain their unresolved implementation/feasibility portions. The accepted naming/completion contracts resolve only specified portions of Q-07. Q-08 client-instance lifetime and global mode scope are defined here; shell environment/cwd/timeouts, key notation, and restoration correlation remain open. No experimental provider/lifecycle/persistence/wire contract is authority.

Implementation verification should cover parsing/selector ambiguity; archive rejection before effects; focus/binding scope; leaf wrapping; direct closure vs reopen; one-owner transfer; merge mapping/loss/partial success; current-owner window restore and original-identity subtree restore; complete backup/history/Undo references; purge token freshness; actual in-flight effects; operation retry/resume/cancellation; shell-invoked CLI independence; and passive presentation. Native full-screen, tab operations, ChatGPT context preservation, notification replay, AX hangs, desktop/Dock recovery, and UI appearance still require supported real macOS qualification. Document validation establishes catalog consistency only, not daemon or OS behavior.
