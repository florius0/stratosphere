# Functional requirements

These requirements record agreed observable behavior. See [concepts](concepts.md) and [decisions](decision-map.md). Mechanisms not settled in the interview remain open questions rather than implied commitments.

## Workspace tree, switching, and focus

- **FR-01:** Support arbitrary-depth workspace nesting. Derive leaf status solely from absence of children. Only leaves directly own windows. Adding children to a populated leaf wraps its windows and layout in a generated child, transfers its saved monitor binding to that child, and leaves the original node as an unbound parent. Users may subsequently bind that parent explicitly.
- **FR-02:** Give workspaces durable UUIDs and normalized, case-insensitively unique sibling names. Names may repeat in different branches. Directories use workspace names and mirror the hierarchy.
- **FR-03:** Allow any node to bind to a physical display, symbolic `main`, or no display. Default leaves to `main`, parents to unbound. The usual setup binds leaves; parent bindings are an explicit grouping option. Main-display changes immediately re-resolve symbolic bindings.
- **FR-04:** Resolve activation bindings from the explicit focus target downward. Bound nodes override descendant bindings for that activation; unbound nodes do not. Later direct focus of a descendant uses its own binding, without retaining overrides from earlier ancestor activation. Only the explicit focus target determines local/global switching; resolving descendants never starts another switch. A leaf is its own terminal selection.
- **FR-05:** Focusing an unbound node globally displays its selected subtree and blanks unoccupied monitors. An unbound leaf appears on the main display. Focusing a bound node switches its target monitor. Crossing projects activates the target project; crossing a narrower scope within a project expands to the lowest common ancestor and retains compatible other-monitor selections.
- **FR-06:** Show at most one leaf per display. Ancestor selection uses remembered selection per display, then recency, then child order. Missing displays fall back to main without changing saved bindings; collision winner is the most recently focused leaf. Reconnection automatically restores that display's selected leaf within the current scope.
- **FR-07:** Leaves restore their last available focused window. Ancestors restore their last focused visible descendant, then the most recently focused available visible window, otherwise the main-display desktop. App-driven window activation selects its owning workspace. Monitor reassignment does not request focus; retain the focused window if visible, otherwise use visible-window recency then desktop.
- **FR-08:** Pinning/recency order applies recursively: pinned siblings in manual order, then unpinned by recency. Activation updates ancestor-path recency; hover, expansion, and history inspection do not. `WorkspaceOrder` is circular and follows the ordered tree; parent ordering starts after its subtree. Navigation snapshots its order until modifier release, explicit selection, or configurable inactivity (one-second default). Skip deleted/archived entries. Close fallback excludes the closed subtree and picks the first remaining leaf, otherwise an empty desktop.

## Lifecycle and structural actions

- **FR-09:** Hidden leaves stay loaded. Exclude automatic unloading. Open and focus restore only selected visible leaves, including leaves previously closed through workspace closure.
- **FR-10:** Close recursively captures available state and releases every loaded descendant, including hidden leaves, within documented integration limits. Reliable/best-effort/unavailable labels do not trigger confirmation prompts. Preflight internally and preserve before-state; unexpected required capture or persistence failure stops affected unsafe steps with nonblocking status and Retry or an explicit recovery action (FR-54, FR-68).
- **FR-11:** Direct app/window closure, including app crashes, marks affected windows closed; workspace reopen does not resurrect them. Retain state/history and provide Reopen Window. Do not supervise or automatically relaunch apps.
- **FR-12:** Archive closes and retains a subtree indefinitely and hides it from normal selection. Archived subtrees are sealed: explicitly unarchive before operational interaction, including moving workspaces/windows into or out of the subtree, reparenting an archived node, merging, or restoring app state. Reject such requests before side effects with a structured unarchive-required result; never implicitly unarchive or close-and-insert incoming contents. Passive inspection, history preview, and backup remain available. Delete recursively closes then moves to recoverable trash, default 30 days; permanent purge is separate and requires explicit confirmation (FR-54). Purge removes the Trash entry and unreferenced semantic data while preserving data still referenced by current state, retained snapshots, or eligible Undo (FR-37, FR-40). History/Undo may therefore still restore the item within declared fidelity. Erasing retained history requires a separate explicit action; its scope is not specified by purge. Archive and moving to trash use internal preflight without confirmation prompts. Archived descendants are excluded even when ancestors are focused.
- **FR-13:** Reparent and focus are separate commands. Sources and destinations must be unarchived; reject reparenting into or out of an archived subtree until explicitly unarchived (FR-12). Ordinary reparenting of a visible workspace preserves loaded state and the active project, recomputes visibility, and hides it if moved outside that project. Exception: moving the active project itself beneath an unarchived destination preserves its current visible scope and focus, while the active project becomes the new top-level ancestor; do not reveal the destination's other branches. UI explains this and can compose Move and Switch. Visible monitor reassignment updates placement immediately; hidden reassignment does not reveal windows.
- **FR-14:** Transfer a window to exactly one destination leaf. Reject archived sources or destinations before ownership changes or restoration; explicitly unarchive first (FR-12). A closed, unarchived destination loads without focus or restoring its other windows. A parent target resolves via remembered selection for the current monitor, recency, and child order, with resolved destination exposed in UI. New ordinary windows join the visible leaf on their display, otherwise the focused leaf; dialogs follow owners. If no leaf is visible, create a Desktop fallback leaf on main.

## Layout and native window behavior

- **FR-15:** Store layout groups and their trees in leaf state, separately from workspace hierarchy. Support one tiled group using BSP or i3-like, plus free and free-centered overlays; each window belongs to one group. Free preserves manual placement. While in free-centered, windows stay centered within usable display space when shown, resized, or placed on another display; initial centering alone is insufficient. Retain engine-specific state when switching tiled engines.
- **FR-16:** i3-like supports horizontal/vertical splits, tabs, and stacks. BSP defaults to splitting the focused tile along its longer axis; insertion target, direction, ratio, and app overrides are configurable.
- **FR-17:** Mouse manipulation reorders tiles, changes divider ratios, or transfers ownership across visible leaves. Making a tiled window floating requires an explicit action/modifier. A deliberate positional drag of a free-centered window switches it to free and preserves the user's chosen position; changes accompanying resize or Stratosphere's centering do not trigger that switch. Otherwise native move/resize changes become user intent within the current group; tiled geometry translates to a supported adjustment rather than being immediately reverted.
- **FR-18:** The green-button hover palette exposes group selection and engine-specific controls. BSP/i3 changes affect the whole tiled group. Command-hover exposes Apple's native menu. Its mechanism must be validated; there is no commitment to undocumented invocation details.
- **FR-19:** Respect reported minimum dimensions where possible. If a layout cannot fit, temporarily float affected windows with a warning, preserving intended tiled membership for return when feasible. Fill expands a tile within its existing tree until neighbors reach minimum sizes; it does not hide them. Free Fill uses usable display area. Content-sized zoom is distinct from Fill.
- **FR-20:** Minimized windows release tile space but retain their tree position. They remain minimized across switching; explicit selection restores them. Native full-screen retains leaf ownership and full-screen mode across workspace switches, temporarily excluding the window from layout. Presenting that window again when returning to its leaf keeps it in native full-screen; normal window-selection/focus rules still apply (FR-07). Explicit full-screen exit restores the prior layout group. Validate this behavior for the selected backend, including virtual-backend coexistence with FR-74 (Q-01).
- **FR-21:** Treat a native tab group as one managed window/layout slot. Detaching creates a new identity in the same leaf. Joining retains destination identity, transfers all contents to its leaf even across workspaces, and preserves absorbed histories. Expose discoverable native tabs as selectable rail children. Container-header visibility, placement, styling, and supported native-chrome options are configurable; visible headers reserve space.

## Integrations and merge

- **FR-22:** Ship built-ins for generic macOS, Safari, Chrome, VS Code, zmx/Ghostty, and ChatGPT. Each window declares reliable/best-effort/unavailable restoration fidelity with explicit limitations explained briefly in integration documentation. Normal use accepts documented limits without first-use or routine confirmation prompts (FR-54). Generic fallback may control geometry/focus while preserving richer integration payloads.
- **FR-23:** Integrations decide matching, compatible window merge, and independent restoration/clone support. Reuse only unique safe matches. Ambiguity leaves candidates untouched and requires resolution unless independent restoration is safe. Individual failures preserve saved state and show retryable placeholders without blocking unrelated restoration.
- **FR-24:** Merge by normalized case-insensitive workspace names recursively into an explicit destination. Sources and destination must be unarchived (FR-12). Destination conflicts win; integrations report losses. Preserve destination ordering/layout slots and insert unmatched incoming windows using destination engine rules. Mixed parent/leaf matches wrap leaf windows into a generated child. Consume/archive the source after successful consolidation and retain pre-merge snapshots. If the source is still the active project when archived after success, follow its previously focused window to the destination leaf, or focus the destination window that absorbed it. If no corresponding window remains available, use the destination's normal selection/focus fallback under FR-04–FR-07. This successful active-source merge uses destination navigation rather than ordinary Close's circular fallback. Partial failure remains visible/retryable; per-source completion and generated-child naming follow the accepted [command catalog](command-catalog.md) (D-30); integration-specific convergence still requires validation.
- **FR-25:** Merge windows only when the integration declares compatibility; unsupported/ambiguous windows stay separate. Destination slot and conflicting state win; source-compatible content is added. Do not infer compatibility from title alone.
- **FR-26:** Safari/Chrome reliable baseline covers URLs, tab order, and active tab. Form drafts and other page state are outside that baseline; explain this briefly in integration documentation without per-close prompts. Private/incognito windows default to placement-only with no persisted URLs, titles, or screenshots; capture is opt-in and restoration is unavailable by default. Explicit history restore enforces saved tabs, internally preflighting extra-tab closure and leaving unrelated windows untouched (FR-54, FR-77).
- **FR-27:** Prefer VS Code CLI/session mechanisms. Define exact fidelity during integration implementation; scope may be reduced. A companion extension is allowed if retained requirements need it, not mandatory from the outset.
- **FR-28:** Users configure zmx/Ghostty; do not ship or rewrite their zmx configuration. Workspace closure detaches terminal presentations and leaves sessions/processes running. User-configured shell launchers receive workspace/window/session identifiers and return explicit live-window correlation. Reattach existing sessions or recreate from available recipes with declared fidelity. Exact protocol/env/result schema remains open.
- **FR-29:** Single-window apps automatically acquire separate leaf-owned contexts on first use, including leaves within the same project. Capture outgoing context and create a fresh incoming context. Only one context per app is live. When multiple visible leaves contain contexts for that app, focusing a leaf requests its context even if another app receives keyboard focus; swapping contexts must not steal keyboard focus from that app. Other contexts show unavailable placeholders. If fresh creation or restoration fails, preserve outgoing content and show a placeholder with nonblocking status and Retry or an explicit recovery action; adopting current content requires an explicit recovery action and never happens as an automatic fallback. Routine switching uses internal preflight without confirmation prompts (FR-54); cancellation preserves outgoing context/selection. ChatGPT must reliably preserve/restore conversation identity and unsent drafts and create fresh contexts. If blocked, workspace switching may proceed with a placeholder while preserving outgoing content; this does not waive the release requirement.

## Files, capture, and external editing

- **FR-30:** Persist workspace metadata as name-based directories containing `workspace.json`, child directories, and UUID-named window JSON under leaves. Store versioned integration-owned readable JSON payloads and separate binary assets. UUIDs preserve identity across path changes.
- **FR-31:** Valid external file replacements immediately become desired state and reconcile live windows, including destructive changes, without confirmation or a conflict-approval workflow. Resolve overlap and newer app activity under FR-76–FR-77. Parsing/readability and necessary tree/lifecycle constraints, including the archive seal, still apply (FR-12); an external edit may explicitly unarchive first. Malformed edits preserve last readable state and original evidence with diagnostics; never treat them as deletion.
- **FR-32:** Valid external directory rename/reparent changes live names/parentage; preserve UUID/history. Apply the archive seal before semantic mutation: archived subtrees must be explicitly unarchived before rename/reparent/delete or transfers involving them (FR-12). Invalid moves/deletions or duplicate sibling names retain last valid semantic state with diagnostics. For an unarchived subtree, debounce disappearance, then close a still-missing subtree and preserve last-known state in trash, without confirmation. Debounce duration is unspecified.
- **FR-33:** Copying a workspace directory creates an independent initially closed clone with fresh workspace/window UUIDs. Integrations declare independent-restoration limits. Distinguishing copy versus move/replacement during multi-file changes requires design (Q-09).
- **FR-34:** Portable workspace backups include semantic tree, contexts, layouts, bindings, closed flags, retained workspace/window history, and structural Undo records with their required state references, within configured retention. Backup restoration restores saved history and eligible Undo; revalidate Undo against the restored/current state (FR-40). Configuration, notification view, screenshots, and machine-local recovery records are separate. Restoring workspace files does not replace those categories.
- **FR-35:** Ordinary app changes update current state before reconciliation can revert them; newer genuine activity supersedes pending reconciliation for the affected item (FR-77). Capture timing is configurable: ordinary current-state writes default to two seconds quiet and at most one write per ten seconds per window. Capture and required persistence at close/merge/restore/explicit save boundaries are immediate and bypass ordinary throttling. Skip unchanged writes. Avoid interpreting failed capture as empty state.

## History and Undo

- **FR-36:** Maintain workspace and window history at meaningful boundaries: explicit capture, closure, merge, accepted external replacement, and history restore. Current-state updates do not create a revision for every tab/resize event. Retain necessary before-state for structural Undo. Periodic snapshots were not explicitly selected.
- **FR-37:** Default retention is the union of all snapshots younger than 24 hours, latest 50 per item, and one daily for 30 days. Pinned snapshots persist until unpinned. Retained snapshots and eligible Undo records must keep all referenced state required for their restoration, even when that state would otherwise expire under another item's retention or its Trash entry is purged. Purge/cleanup must not invalidate these references; reclaim semantic data only when no current-state, retained-snapshot, or eligible-Undo reference still requires it. Retention is configurable; identical payloads share storage.
- **FR-38:** Overview timeline previews latest per-item state at/before selected time and exposes actual timestamps. Selectively restore a window or subtree only on explicit action; no automatic whole-desktop time travel.
- **FR-39:** Snapshot current state before restoration. Restore selected contents exactly, closing/removing newer additions under internal preflight (FR-54). Preserve selected node identity/name/parent, while restoring child structure/names/parentage beneath it. An individually selected window keeps its managed identity and current leaf owner while restoring captured state within that leaf; structural Undo handles its own transfer. If a captured descendant now exists outside the selected subtree, move the original back to its captured position and restore its captured contents, preserving UUID/history instead of creating a duplicate. Likewise, a window captured under the selected subtree that has since transferred elsewhere returns as its original managed identity to its captured leaf owner and restores its captured state, subject to safe matching/restoration (FR-23). Leave unrelated contents at the former parent/owner untouched; include original placement/ownership and state in the restoration before-state so structural Undo can reverse these moves. Tree/identity invariants and the archive seal still apply: archived sources/destinations require explicit Unarchive before affected restore/move steps, without implicit unarchive (FR-12). Undo handles the selected node's own rename/move.
- **FR-40:** Offer direct Undo for completed structural mutations using before-state and preflight; conflicts may make it unavailable. Persist availability across restarts within retention. Shell/arbitrary app actions are not undoable. Interrupted operations use Resume, not completed-operation Undo. Redo semantics remain unspecified.

## Rail, overview, and appearance

- **FR-41:** Provide native-feeling Liquid Glass rails on connected displays using one global configuration and no per-display overrides. Show shared tree/launchers and highlight each display's visible leaf. Clicks respect bindings, not the clicked rail's display.
- **FR-42:** Compact mode shows project squircle icons. Full mode expands active paths and their windows, retaining user-controlled expansion for others. Integration children expand on demand. Hover previews are interactive tree popovers with configurable dismiss delay, no activation/restoration/recency change before an action.
- **FR-43:** Replace Mission Control interaction with entire tree, live loaded previews, saved closed previews, search, window transfer, reparenting, and timeline/selective restore. Three-finger swipe up opens it by default and is configurable; retain hotkey/rail access and configurable native Mission Control access.
- **FR-44:** Rail includes global app launchers, separators, filesystem-folder stacks, and configured launcher folders, distinct from workspace nodes. Launcher click follows app MRU managed window; otherwise invokes configured launch. Expose New Window in Current Workspace separately when supported.
- **FR-45:** Visible rail reserves usable layout space. Autohide overlays without reflow; edge hover and toggle hotkey reveal it. Keep it visible during previews/stacks/menus, then hide after configurable delay. Full/compact size changes affect reserved space only in visible mode.
- **FR-46:** Persist screenshots separately, enabled by default except private windows, with configurable capture/retention. Screenshot fidelity, permissions, and history correspondence require implementation validation; images are presentation, not restorable app state.
- **FR-47:** Show notifications and integration status/actions in rail. Default look is restrained native Liquid Glass with configurable UI animation, instant switching, and borders/corner overrides disabled until enabled. Do not leak implementation details into ordinary UI flows.

## Notifications

- **FR-48:** Preserve Apple's banners. Materialize retained notifications in separate files suitable for independent Git/backup exclusion. Mirror Apple's retained records/removals; mark cached view stale when inaccessible. Banner disappearance alone is not source-record removal.
- **FR-49:** Attribute to windows/workspaces best effort. Ambiguity falls back to the app's most recently focused window. Actual app-selected window activation overrides predicted attribution. Do not claim database changes alone identify a click.
- **FR-50:** Native notification clicks select the corresponding workspace/window where identifiable; keep normal app behavior. A rail click navigates and attempts the original action. If replay fails/unavailable, navigation still succeeds with a visible limitation, without inventing unrelated actions.
- **FR-51:** Investigate private response dispatch alongside integration actions and AX interaction; private APIs are allowed. Replay/click detection and exact fallback priority are unresolved mechanisms. Never mutate Apple's notification database as an invocation technique.

## API and execution

- **FR-52:** Expose versioned JSON-RPC over a local user-restricted Unix socket. UI is a thin client; every UI action has CLI/daemon coverage, including presentation controls where appropriate. Third parties may use IPC, CLI, or files.
- **FR-53:** Accepted operations return IDs, progress/status, and results and continue after disconnect. Cancellation stops remaining cancellable work without undoing side effects. Preserve partial completion and captured state; report succeeded/failed steps with Retry.
- **FR-54:** Run daemon preflight internally before side effects, checking invariants and required capture/persistence and preserving before-state. Ordinary switching, opening, closing, transferring, archiving, moving to trash, merging, history restore, and supported Undo proceed without confirmation prompts within documented integration limits. Best-effort/unavailable fidelity alone does not prompt. Unexpected failures stop affected unsafe steps, expose nonblocking status and structured results, and offer Retry or an explicit recovery action without an automatic confirmation dialog. History/Undo protects structural changes where supported; app restoration remains limited to declared guarantees. Permanent purge requires explicit confirmation: interactive CLI prompts, noninteractive calls return structured confirmation-required results, and UI uses the same daemon preflight. Purge preflight explains the Trash entry/data being removed and historical/Undo references being preserved, including that retained history may still restore the item (FR-12, FR-37). Token binds purge consent to affected state/risks; changes invalidate it. Explicit force accepts current purge risks, without bypassing invariants or required capture/persistence. External-file adoption remains a no-confirmation path.
- **FR-55:** Persist operation progress. After daemon crash, recover desktop first and require explicit Resume/Retry of interrupted work. Do not automatically continue close/merge/restore after restart. No speculative rollback.
- **FR-56:** Snapshot/event subscriptions support thin clients and reconnect. Protocol framing/version gates, overflow handling, and operation-retention details are to be designed; do not copy the experimental wire contract by assumption.
- **FR-57:** Per-client action sequences preserve order. A CLI process invoked by a shell is a separate client with its own queue. Globally order short state planning/commits; run shell/AX/integration waits outside the mutation queue and revalidate freshness. Other clients may plan and commit state during pending operations or launchers. Coordinate concrete side-effect steps and activity precedence under FR-75–FR-78 without holding the global queue across external waits. Do not hold the global queue while a shell invokes the CLI. Fine-grained locks are deferred; coordination mechanisms remain open (Q-13).

## Overlapping operations and reconciliation

- **FR-75:** Scope overlap waiting to concrete side-effect steps, not entire operations, workspaces, or windows merely because a launcher/operation is pending. Other clients may plan and commit state under FR-57. Defer a conflicting app-effect step while an overlapping app call's outcome remains unresolved, or when the step requires a live window not yet identified. On resolution, replan that step against the latest state and rerun internal preflight; reconfirm only when required by FR-54. For example, another client can change a saved window's destination leaf during launch; later live-window correlation and placement use its current owner. Record already-issued effects and reconcile to latest intent. Unrelated work continues; pending steps can be cancelled without undoing completed effects.
- **FR-76:** A valid external edit immediately supersedes conflicting operation steps not yet issued. Stop those steps, allow unavoidable in-flight calls to finish, record their effects, then reconcile to the latest desired state. Do not retry superseded intent. External adoption still requires no confirmation and does not bypass validity or required durability checks.
- **FR-77:** Newer genuine user/app activity supersedes pending reconciliation for the affected item only; continue unrelated parts of the reconciliation. For example, navigating a tab after an external edit requests its removal cancels the pending closure of that tab. Events caused by Stratosphere's own actions do not count as new activity. Already-issued effects cannot be assumed cancellable; record them and reconcile to the latest desired state. Activity attribution and ordering mechanisms remain open (Q-13).
- **FR-78:** If overlapping app work stalls, keep dependent side-effect steps pending with visible blocked status and cancellation. Other clients' planning/state commits and unrelated work continue (FR-57, FR-75). When the app responds, replan pending steps against the latest state. Daemon-crash interruption instead requires explicit Resume/Retry (FR-55). The delay before showing blocked status remains open (Q-04).

## Configuration and ricing

- **FR-58:** Use TOML configuration with a native Home Manager module generating the same shape. Writable UI override layer wins over base values, identifies overrides, and supports Reset to Configured Value. Workspace state remains separate.
- **FR-59:** Shell action shape is `{ name? , shell, async = false }`; support named actions, mode-bound hotkeys, and restoration hooks with the same shape. Arbitrary Bash commands are allowed. Restoration additionally requires context input and explicit correlation output.
- **FR-60:** Support named modes and ordered action sequences. Built-in steps complete before next step; synchronous shell waits within its execution instance, async explicitly backgrounds. Stop sequence on failure unless configured otherwise. Exact client/execution-instance lifetime needs definition.
- **FR-61:** Preserve deliberate hotkey presses, coalesce navigation/resize key repeats, never coalesce destructive actions. Configure focus-follows-mouse and mouse-follows-focus independently; prevent feedback loops. Defaults for these two flags were recommended but not explicitly accepted.
- **FR-62:** Window rules default to discovery/restoration; continuous matching is opt-in. Matching rules accumulate in config order until explicit stop; later assignments override earlier ones. Ordinary title changes do not trigger implicit transfers under default policy.
- **FR-63:** Ricing includes custom borders, global corner-radius override, and animation controls, including switching animation (instant by default). Optional effects may depend on SIP configuration/capabilities; core behavior does not. Exact supported mechanisms remain research-dependent.

## Recovery, process lifecycle, and release

- **FR-64:** On explicit shutdown restore surviving managed windows onscreen and their pre-management geometry where available; later-created windows use first-observed geometry. Do not recreate intentionally closed windows or rewind app state. Persist recovery geometry before takeover mutations.
- **FR-65:** Independent watchdog performs immediate recovery after crash and confirmed daemon hang. Heartbeat is independent of app AX stalls. Recover windows/Dock first, then restart with bounded backoff; repeated failure leaves management stopped with a diagnostic. Exact timeout/retry bounds remain open.
- **FR-66:** Watchdog restarts enabled rail after unexpected failure while daemon continues. Rail has no Quit action and ignores Command-Q. Explicit Shut Down Stratosphere UI/CLI stops all components; configuration disables rail and restores Dock by default, with an option to leave Dock hidden.
- **FR-67:** Startup reorganizes surviving windows without launching apps/recreating missing windows. Accessibility revocation leaves daemon/UI/CLI alive diagnostically, stops mutations, attempts recovery where possible, and resumes when access returns. Other permission losses degrade only dependent capabilities.
- **FR-68:** Storage failure blocks operations needing new state/recovery records and unsafe closure; preserve diagnostics and safe already-loaded navigation. Automatic app quit is opt-in, graceful only, and requires proof of no relevant managed/unmanaged windows and no integration keep-alive need; never force-kill apps.
- **FR-69:** Package self-contained app with rail, daemon, CLI, watchdogs/helpers. Enable login startup after setup, configurable in UI/Home Manager; only one login mechanism active.
- **FR-70:** Provide standalone updater, Homebrew cask/CLI availability, and Nix packages/module. Updates follow installation origin: direct updater, brew upgrade, or Nix. Preserve state and use explicit shutdown/restart recovery flow.
- **FR-71:** Home Manager defaults to official signed/notarized bundle, with source-build/persistent local-signing option. Publish exact tested macOS and integration-app matrix with each release. No runtime adaptive private-feature breakage handling is required; compatibility is part of development/release testing.
- **FR-72:** Prefer native Spaces if they satisfy all agreed semantics; otherwise use virtual workspaces. Developers select backend at compile time; no user selection or automatic runtime switching.
- **FR-73:** Native-backend first import requires reliable complete Space/window discovery and maps leaves to native Spaces/display assignments. Automatic import preserves geometry in free placement under Desktop root and records recovery before takeover. Determine feasibility during development.
- **FR-74:** If using virtual backend, automatically manage visible eligible windows while warning about native Spaces incompatibility and required settings. Native-Space changes trigger no special handling; users apply settings. Conflicting manager detection/blocking is out of scope.

## Public command contract

- **FR-79:** Provide the resource-first command/action surface defined in the [command catalog](command-catalog.md), including its selectors, explicit targets, defaults, query semantics, operation results, exit codes, presentation actions, and recovery paths. CLI, UI, and configured built-in actions share daemon semantics. Accepted command design does not establish private-API feasibility or choose unresolved transport/storage mechanisms; existing capture, durability, archive, ownership, and consent requirements remain mandatory.
