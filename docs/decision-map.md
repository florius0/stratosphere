## Revisions agreed on 2026-10-09

- **D-11, D-17:** Replace the earlier risky-close/context-switch confirmation rule and proposed remembered-consent workflow with ordinary actions that run without confirmation prompts (FR-10, FR-22, FR-26, FR-29, FR-54). Documented integration limits are accepted in normal use; a short explanation in the docs is sufficient. Permanent purge retains explicit daemon-bound consent. Unexpected failures stop unsafe steps with nonblocking status and Retry or an explicit recovery action. This preserves required capture, durability, invariants, and the ChatGPT reliability release gate; history/Undo does not expand app-restoration guarantees.
- **D-15, D-18:** Specify overlapping-operation and reconciliation behavior (FR-75–FR-78): conflicting user requests wait/replan, external edits supersede unissued conflicting work, and newer genuine app activity supersedes pending reconciliation for the affected item. Stalled requests remain pending and cancellable. The earlier interview's fresh-confirmation rule for waiting requests now applies only where FR-54 requires it. Mechanisms and numerical hang bounds remain open (Q-04, Q-13).
- **D-12:** Resolve the earlier project-context granularity as separate contexts per leaf, including leaves within the same project (C-04, FR-29). When multiple visible leaves contain an app's contexts, the focused leaf requests the live context even when another app receives keyboard focus. Swapping contexts must not steal keyboard focus. Only one context per app remains live; failed switches preserve outgoing content and expose the requested context as a placeholder.
- **D-16:** Exact subtree restoration brings captured descendants moved elsewhere and captured windows transferred to other leaves back as their original identities, restores their captured contents under safe integration matching/restoration, preserves unrelated source contents, and records original placement/ownership and state for structural Undo (FR-23, FR-39). An individually selected window instead keeps its current leaf owner and restores captured state within that leaf; structural Undo handles its own transfer. Portable workspace backups include retained history and eligible structural Undo alongside current semantic state (FR-34); retained records keep their required restoration references (FR-37). Configuration, screenshots, notification content, and machine-local recovery remain separate. This does not expand integration fidelity.
- **D-03:** Clarify that ancestor monitor overrides apply when resolving that activation, and later direct descendant focus uses the descendant's own binding (C-02, FR-04). Normal setup binds leaves and leaves parents unbound; explicit parent bindings remain supported (FR-03). When a populated leaf gains children, its binding moves with its windows/layout to the generated child and the original node becomes an unbound parent (C-01, FR-01). Moving the active project itself under an unarchived destination preserves its visible scope/focus and makes the new top-level ancestor the active project; this explicitly qualifies the earlier active-project preservation rule (C-03, FR-13).
- **D-10:** After successfully merging the active project and archiving its source, focus follows its previously focused window or the destination window that absorbed it; if unavailable, use destination selection/focus fallback. This replaces ordinary Close fallback for successful active-source merges (C-03, FR-24). Partial-failure and merge-success criteria remain as documented in Q-07.
- **D-08:** Define free-centered as maintaining centering within usable display space on show, resize, and display placement (C-06, FR-15). Deliberate positional drag switches it to free and preserves the chosen position; resizing and manager-generated positioning keep it centered. This explicitly qualifies the earlier native-movement-within-current-group rule for free-centered dragging; tiled-to-floating still requires an explicit action/modifier (FR-17).
- **D-09:** Workspace switching preserves native full-screen mode and leaf ownership; presenting the window again keeps it full-screen, while explicit exit restores its prior group (C-06, FR-20). Normal focus/selection remains in force. This is required behavior whose mechanism must be validated for the selected backend; virtual-backend coexistence with FR-74 is explicitly part of Q-01, without selecting a mechanism or adding runtime backend fallback.
- **D-04, earlier revision — superseded:** Initially allowed recursively closing incoming contents before moving them into an archived subtree. The subsequent sealed-archive revision below replaces this behavior.
- **D-04, subsequent revision:** Archives are sealed until explicitly unarchived. Reject operational interaction before side effects, including workspace/window transfers in or out, reparenting an archived node, merge, and app-state restoration. There is no close-and-insert path or implicit unarchive; passive inspection, history preview, and backup remain available (C-05, FR-12–FR-14). This supersedes the earlier archive-insertion rule.
- **D-18, scope refinement:** The earlier wait-and-replan rule applies to concrete conflicting side-effect steps, not whole operations/workspaces/windows merely because a launcher is running. Separate clients, including CLI processes invoked by shells, may plan/commit state through the short mutation queue; later live-window correlation/placement uses current state. Only steps depending on an unresolved app effect or missing live-window identity wait (C-09, FR-57, FR-75–FR-78). Fine-grained locking and mechanisms remain open (Q-08, Q-13); the shared action shape and `async = false` default are unchanged.
- **D-16, purge scope:** Permanent purge removes the Trash entry and unreferenced semantic data, preserving data still needed by current state, retained snapshots, or eligible Undo. Retained history follows existing retention rules; pinned snapshots remain complete and history/Undo may still restore the item within declared fidelity (C-05, C-08, FR-12, FR-37, FR-40). Purge preflight explains removed and retained data (FR-54). Erasing retained history would require a separate explicit action with its own specification; this revision does not define that action or its scope. Reference tracking and cleanup mechanisms remain open (Q-09).
- **Documentation alignment:** C-09's shell action requires `shell`, matching FR-59. FR-35's ordinary current-state write throttle excludes immediate boundary capture/persistence. F-14's safe-update dependency on F-13 is now explicit in Markdown, matching FR-70 and the existing feature diagram.

## Evidence informing AX decisions

Research inspected AeroSpace main at commit `74a1bf1` (2026-10-01). It uses a thread/run loop per application, not per window. [MacApp source](https://github.com/nikitabobko/AeroSpace/blob/74a1bf1/Sources/AppBundle/tree/MacApp.swift) and [run-loop cancellation](https://github.com/nikitabobko/AeroSpace/blob/74a1bf1/Sources/AppBundle/runLoop.swift) establish confinement and cooperative cancellation.

[Issue 131](https://github.com/nikitabobko/AeroSpace/issues/131) documents the history: one-second AX timeout mitigation in 2024, [per-application threading in April 2025](https://github.com/nikitabobko/AeroSpace/commit/27689c6bfb153c320e03c9becfb54da0a4df4077), [explicit timeout removal](https://github.com/nikitabobko/AeroSpace/commit/535e4864edfd262cba71630c70d00ae9c23f2842), and 0.18.0 release. [Maintainer tests](https://github.com/nikitabobko/AeroSpace/issues/131#issuecomment-2781506520) reported Java/pygame hang containment but residual Godot delay. These observations inform the baseline, not proof of Stratosphere's recovery guarantee.
