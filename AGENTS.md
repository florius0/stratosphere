# Repository guidelines

## Product authority — read before work

Stratosphere is a new standalone Swift macOS window manager and project-context manager. The earlier implementation was an experiment and does not constrain this design. Do not recover its old contract as authority or silently reuse its provider, lifecycle, persistence, or wire semantics.

Start with [docs/overview.md](docs/overview.md), then read the documents relevant to the task:

- [docs/concepts.md](docs/concepts.md): vocabulary, tree/binding/identity invariants (`C-*`).
- [docs/feature-map.md](docs/feature-map.md): scope, dependencies, exclusions (`F-*`).
- [docs/functional-requirements.md](docs/functional-requirements.md): observable behavior and failure paths (`FR-*`).
- [docs/non-functional-requirements.md](docs/non-functional-requirements.md): reliability, isolation, durability, security, packaging (`NFR-*`).
- [docs/decision-map.md](docs/decision-map.md): agreed decisions (`D-*`), open research (`Q-*`), and evidence.

The matching `.dot` files are summaries; Markdown is authoritative. Preserve stable IDs, cite affected requirements in implementation plans/reviews, and update concepts/requirements/decisions and diagrams together when behavior changes. Keep unresolved mechanisms unresolved until validated. Document explicit revisions instead of silently weakening accepted requirements. Implementation planning is separate from these product documents; the selected foundation layout and scope are recorded in [the foundation design](docs/implementation/2026-10-09-foundation-design.md) and [implementation plan](docs/implementation/2026-10-09-foundation-plan.md).

## Contracts easily missed

- Arbitrary-depth tree; leaf status derives from children. Only leaves own windows. One ordinary window has one leaf owner. Adding children to a populated leaf wraps windows/layout and transfers its binding into the generated child, leaving the original node an unbound parent.
- Any node can be monitor-bound or unbound. Normally leaves are bound and parents unbound; parent binding is explicit. Bound ancestors override descendants during that activation; later direct descendant focus uses its own binding. Explicit focus target alone sets switching scope. Global switches blank unoccupied monitors and preserve one project hierarchy.
- Hidden leaves remain loaded. No automatic unloading. Close is recursive; open/focus restores visible leaves only. Direct app/window closure stays closed; do not supervise apps.
- Layout groups are leaf properties: one BSP/i3-like tiled group plus free/free-centered. Free-centered maintains centering on show/resize/display placement; deliberate positional drag selects free. Resize/manager positioning does not change groups; tiled-to-floating requires an explicit action/modifier. Fill stays within layout; respect minimum dimensions. Native tabs are one managed window, separate from browser tabs/i3 tabs. Native full-screen preserves mode/ownership across workspace switches and restores the prior group on explicit exit; selected-backend mechanisms remain unvalidated (Q-01).
- Deep merge uses case-insensitive sibling names and destination precedence, integration-defined window compatibility, history, and source archive after success. Successful active-project merge follows the previously focused window or its absorbing destination window; otherwise use destination selection/focus fallback.
- Moving the active project itself under an unarchived destination preserves its current visible scope/focus while its new top-level ancestor becomes the active project. Ordinary cross-project reparenting still hides moved visible subtrees without switching. Archived subtrees are sealed: explicitly unarchive before operational interaction, including workspace/window transfers in or out. Reject such requests before side effects; never implicitly unarchive or close-and-insert. Passive inspection, history preview, and backup remain available.
- Single-window apps have separate leaf-owned contexts, including leaves within one project, with one live context per app. The focused leaf wins among visible contexts even when another app receives keyboard focus; swapping contexts must not steal that focus. Reliable ChatGPT conversation and draft restoration is a release gate. VS Code remains CLI-first with scope revisitable. Users configure zmx/Ghostty launchers and correlation; arbitrary Bash actions are allowed.
- Ordinary actions run without confirmation prompts within documented integration limits, including best-effort/unavailable fidelity. Daemon preflight is internal; permanent purge requires explicit consent bound to preflight. Unexpected failures stop unsafe steps with nonblocking status and Retry or an explicit recovery action. Required capture/durability and invariants still apply. Valid external edits immediately reconcile without confirmation. Malformed edits retain last readable state. Name-based directories and UUIDs support live rename/reparent/delete/copy semantics.
- History is boundary-based with selective restore and persistent structural Undo. Window-only restore keeps its current leaf owner; structural Undo handles its own transfer. Subtree restore brings original moved descendants and transferred windows back with UUID/history under safe matching/restoration, and records prior placement/ownership and state for Undo, leaving unrelated source contents untouched. Portable semantic backups include retained history/Undo and required references; retained snapshots must stay complete. Trash purge removes the entry and unreferenced semantic data, preserving data required by current state, retained snapshots, or eligible Undo; history/Undo may still restore the item. Erasing retained history requires a separately specified explicit action. Notification content/screenshots/configuration/recovery records are separate from semantic backups. Private/incognito capture defaults off.
- Rail is a thin client/Dock replacement with one shared configuration, no per-display overrides, passive interactive hover previews, and whole-tree overview/timeline. No rail Quit, ignore Command-Q; only explicit Stratosphere shutdown. Config can disable rail.
- Native notification banners stay. Rail mirrors Apple's retained records in separate files; actual app-chosen target wins, ambiguous attribution uses app MRU. Rail click navigates and attempts original action; private replay is not yet proven.
- Per-client action ordering plus globally ordered short state mutations. CLI processes invoked by shells have their own client queues. Wait/replan only concrete conflicting side-effect steps or steps awaiting required live-window identity; pending operations/launchers do not lock whole workspaces/windows. Other clients may plan/commit state; later window correlation uses current ownership/state. Stalled dependent steps remain pending with blocked status/cancellation. External edits supersede unissued conflicting steps; newer genuine app activity supersedes pending reconciliation for that item. Record unavoidable in-flight effects. Do not hold the mutation queue while shell/AX/integration calls run. Fine-grained locks remain deferred; coordination mechanisms remain unresolved (Q-13).
- Per-application AX threads baseline, not per-window; process escalation depends on hang tests. Independent watchdogs restore desktop/Dock after crashes/hangs and restart with bounds. Interrupted operations require explicit resume.
- Swift, macOS 26+ Apple Silicon, SIP-enabled core. Private APIs allowed. Backend selected by developers at compile time; virtual backend ignores native-Space switching and user configures settings. No competing-manager gate or runtime private-feature compatibility policy.
- TOML config, readable versioned JSON state/API, Home Manager base plus writable UI overrides. JSON-RPC over local user socket; framing/overflow details are open.
- Self-contained app, signed/notarized distributed builds, Homebrew/direct/Nix updates by origin, official bundle default for Nix with optional local source build. Publish tested-version matrix.

## Development and verification

For UI and animation work, read [docs/design-process.md](docs/design-process.md). Use the native Storybook approach: shared production components, reproducible stories, and replayable interaction scenarios. Include representative stories with UI changes and interruption scenarios with important animations; validate final appearance and desktop behavior on supported macOS.

This checkout implements the current development scope: a workspace domain model, shared native UI components and story catalog, build/bundle tooling, and isolated-environment probes. Use the existing build/test commands in [README.md](README.md#development), including `nix run .#test` and `nix flake check`, and the documentation check `nix run .#docs`. Use Git-backed flake references: filesystem/path flake imports can ingest ignored `.local` VM disks. See [development verification](docs/implementation/development-verification.md) for recorded evidence and qualification limits. The window-management daemon, public socket API, persistence engine, integrations, and recovery watchdogs remain unimplemented; development checks do not establish those product capabilities. Use Swift tooling for source work and Nix for reproducible builds.

Validate OS-dependent claims on real supported macOS configurations; deterministic fakes cannot establish private-API feasibility. Keep deterministic tests free of live personal app data. Run checks appropriate to changes and report what was actually verified.

For documentation, validate relative links and stable-ID references, parse all DOT files with Graphviz when available, inspect diagrams, and check diffs for omissions/contradictions. Do not add generated diagram files to source unless requested or adopted by a later docs workflow.
